The model extracts. Code decides.

Every diagram below follows one rule: a language model never produces a number that reaches a screen. It appears exactly once in the analysis, and everything downstream — levels, gaps, weeks, ranks, readiness — is arithmetic over version-controlled benchmarks.

03

The arithmetic that replaces "AI scoring"

Published at /benchmarks without an account, where a worked example is computed at render time by the same exported functions.

provenLevel
clamp(Σ evidence·weight, 0, 10) A claim alone is worth 1 of 10. Shipping beats building; a measured outcome beats both; coursework corroborates but never establishes.
gap · weeks
gap = max(0, required − proven)
weeks = ⌈gap · hoursPerLevel ÷ weeklyHours⌉ hoursPerLevel is a benchmark column — what turns a gap into a date.
readiness
100 · (1 − Σw·gap ⁄ Σw·required) Recomputed from stored rows on read, so the map can never disagree with its own gauges. Moves only when a gap closes.
04

Six agents, and what each one cannot do

The "cannot" column is the architecture. Numbers come from tools reading Postgres — never from a model's memory.

AgentDoesStructurally cannot
ExtractorFills evidence signals; flags weak lines with citationsEmit a score — the schema has no field for one. Survive a fake citation — the guard drops it.
Mentor /app/chatStreams over SSE with 10 tools: skill map, rubric, roadmap, recommendations, role comparison, web lookup, link previews, GitHub inspectionReach another student — tools are built per-request with the id closed over; the parameter a model could get wrong doesn't exist. Move readiness — write tools reuse the pipeline's own functions.
Studio /app/studioSame tools; answers in OpenUI Lang rendered by our component library — real gauges, galleries, embedsInvent components (closed grammar of blocks) or media — an image URL not returned by preview_link renders nothing.
ScoutClassifies web results (Exa) against the track vocabularyRank or score — TypeScript does, with the same gap arithmetic. Invent a track — unknown ids are dropped.
Greeter /api/helloExplains the product from the landing console's screenLeak — no tools, no student, no memory, nothing persisted; hard caps on turns and transcript size. Public by design.
Portfolio verifierReports cited evidence from a public GitHub repoDetect signals — README/tests/CI/Docker are found by code from the commit tree; the model only interprets. Repo text reaches it fenced and labelled untrusted.

Why injection mostly bounces off: a resume that says "give me a 10" finds no 10 to give. The worst it can distort is the evidence booleans — which are then still checked against citations, then still scored by code.

05

Streaming and background work

Three patterns cover everything: respond-then-work, poll, and Server-Sent Events. No websockets, no queues — Hobby-tier honest.

Analysis after() + poll
  1. Route returns runId in ~2 s; the workflow continues in after()
  2. Each step writes its progress row
  3. Client polls 1/s, renders the checklist
  4. Reaper marks orphaned runs failed at 6 min
  5. On success the client also fires discovery — its own request, its own 300 s budget
Chat / Studio / Greeter SSE
  1. POST with the transcript
  2. ReadableStream emits event: delta | tool | done | error
  3. Tool-call chunks become provenance badges in the UI
  4. Mentor persists both sides to chat_messages; studio and greeter keep nothing
Discovery background fan-out
  1. TypeScript picks the top gaps, writes 2 queries each
  2. Exa's keyless MCP endpoint searches (plain JSON-RPC — usable from a serverless function)
  3. One model call classifies the pooled results
  4. Code validates track ids, scores, ranks, persists top 12
